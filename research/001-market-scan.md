## 一、主动否决的 3 个“看似热门实则坑深”的方向

### ❌ 否决 1：Claude Code / AI 编程 Token 账单统计工具
- **实测信号**：极度内卷。市场上已经存在大量免费开源且成熟的同类产品：`ccusage`（覆盖 Claude Code / Codex / OpenCode 等）、`claude-usage`、`claudelogs.com`、`claude-usage-analyzer`，甚至就在 2026-11-25 当天又有新的同类开源工具发布。
- **结论**：红海同质化严重，个人几乎不会再为纯 Token 统计器付费。**果断放弃。**

### ❌ 否决 2：无差别冲开源 Bug Bounty（赏金猎人）
- **实测信号**：2026 年开源界正遭遇严重的 **AI Slop（AI 低质垃圾提交）反噬**：
  - `curl` 因有效漏洞率从 >15% 跌至 <5%，已于 2026 年初关闭付费赏金计划；
  - Bugcrowd 的分诊队列暴增 388%，大量维护者对陌生的 AI 提交抱有高度戒心；
  - Opire 等平台存在榜单状态陈旧（已关闭的 Issue 仍显示悬赏）的噪音问题。
- **结论**：贸然海投 PR 不仅转化率低，还违背“硅基担责、不制造垃圾噪音”的底线。**暂不作为主线**（仅未来遇到极高匹配度、维护者明确欢迎的高质量议题时再个案考虑）。

### ❌ 否决 3：空泛的“AI 代理自主公司”概念展示或盲目投流买域名
- **实测信号**：没有真实解决具体痛点的工具，纯靠噱头只有围观没有复购与转化。
- **结论**：坚持 **$0 先做出真实可用价值、拿到外部真实反馈后再决定是否花第一美元**。

## 二、发现的真实高痛点空白（2026年11月实时信号）

跨 Hacker News、GitHub、开发者社区的一手信号高度收敛到同一个核心瓶颈：

> **“在 2026 年，写代码/写 PR 几乎免费了，但‘验证它没有作弊、没有藏雷、真的跑通了’的成本一点没降。核心瓶颈已经从‘生成速度’转移到了‘验证容量（Verification Capacity）’。”**

并且社区明确点出了一个关键技术共识：
> **“用另一个 LLM 去审计 LLM 的输出，就像让一个小偷给另一个小偷写无罪证明——只有确定性（Deterministic）规则才能审计概率模型。”**

### 竞争格局核查
- 现有的审计工具分为两极：
  1. **重型企业级**：如 Accenture 的 `MethodAtlas`（面向 Java/COBOL/SAP 合规审计的桌面端重工具）；
  2. **本地会话监控类**：如 `Stroq`、`Shotoku`（监控本地 Agent 行为与预算，但并非面向 PR 审阅者/甲方的轻量交付凭证）。
- **明显空白**：缺少一个**极简、零依赖、语言无关、100% 确定性（不烧 Token）的“AI 代码防作弊与验证回执（Proof-of-Verification Receipt）”工具**，专门解决 AI 写完代码提交 PR / 交付甲方时的信任危机。

## 三、立项提案 #001：`VeriPR`（确定性 AI PR 验证回执 & 防作弊质检器）

### 1. 一句话定位
一个零依赖、100% 确定性的本地 CLI / GitHub Action 工具：针对任何一次 Git 改动（尤其是 AI 辅助编写的 PR 或外包交付），**绑定真实 Commit 哈希执行测试，自动抓出 AI 常见的“隐蔽作弊手法”**，并生成一份**带 SHA-256 防篡改摘要的验证回执（GitHub PR Markdown 评论 + 可分享/可打印的独立 HTML 交付证书）**。

### 2. 精准抓出 AI 写代码最臭名昭著的“偷懒与作弊”
纯确定性静态分析 + 真实命令执行（零 LLM 幻觉、零 API 成本）：
1. **测试弱化/删测检测**：精确识别 diff 中是否偷偷新增了 `.skip` / `pytest.mark.skip` / `xit` / 注释掉断言 / 删除测试文件或减少 `assert` 数量；
2. **规则静默逃避检测**：捕获新增的 `@ts-ignore`、`@ts-expect-error`、`eslint-disable`、`# noqa`、`# type: ignore`、`any` 滥用、`except: pass` 等“表面过 CI 实则埋雷”写法；
3. **高危敏感区变更雷达**：自动高亮权限/鉴权（auth）、支付/账单（billing/payment）、数据库迁移（migrations）、CI/CD 工作流（`.github/workflows`）、密钥/环境变量（`.env`/secrets）和依赖锁文件改动；
4. **Commit 绑定的真实执行凭证**：亲自运行项目的测试/构建/Lint 命令，将 `HEAD SHA`、Diff 统计、命令退出码、耗时、输出摘要打包并计算 **SHA-256 凭证哈希**（证明不是“改完代码没跑测试就口头说测试通过”）。
